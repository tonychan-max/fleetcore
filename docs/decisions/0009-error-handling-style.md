# 0009. エラー処理はエラーコードで行い、影響範囲を型で表す

## 状態

**採用（暫定）** — 2026-08（Step 2 で実装）

> C++23 に移行できる時点で再検討する。検証方法を参照。

## 背景

Step 2 で外部入力を扱うコードを書き始めた。エラー処理の方式を決める必要がある。

前提として、この系で起きる失敗のほとんどは**異常ではなく想定内の事象**である。

- 不正なバイト列が届く
- 端末が存在しない
- 相手プロセスが起動していない

これらは通信システムでは日常的に起きる。「例外」と呼ぶには頻度が高すぎる。

実務では C++/MFC・C# ともに try/catch を主に使っている。
その差分自体が学習項目である。

## 選択肢

1. **例外（try/catch）**
2. **エラーコードを返し、値は出力引数で受け取る**
3. `Result<T, E>` 相当の型を自作する（成功値と失敗理由を1つの戻り値に包む）

## 決定

**案2。ただし `Result<T,E>` への移行を前提とした暫定判断とする。**

加えて、**エラーの影響範囲を `Severity` として型で表現する**（`common/error_policy.h`）。

| Severity | 意味 | 制御 |
|---|---|---|
| `Message` | この電文だけが不正。次の電文へ | `continue` |
| `Stream` | バイト列が同期を失った。以降解析不能 | `break` |
| `Peer` | 特定の端末が不達。他端末は継続 | 記録して継続 |
| `Process` | 継続不能。終了して supervisor に任せる | `return 1` |

## 理由

- **想定内の失敗を例外で扱うと、正常系と異常系の区別が消える。**
  「電文が1つ壊れていた」と「メモリ確保に失敗した」が同じ機構で流れるのは、
  読む側にとって情報量が減る
- **`Severity` を型にすることで、回復戦略がログと呼び出し側の両方から見える。**
  `continue` か `break` かというコードの形からではなく、名前から分かる
- 案3が本来望ましい。ADR-0005 で既に `Result<Route>` を前提とした
  インタフェースを定義しており、**現状はそれと不整合である**
  → ただし C++17 には `std::expected` が無く、自作は Step 2 の範囲を超える

⚠️ **要確認**：車載・組込み分野で例外が禁止されることがある、という一般論を
根拠にしたい誘惑があるが、AUTOSAR / MISRA の具体的な条文を確認していない。
**この ADR はその一般論に依拠していない。** 上記の理由だけで成立する。

## 代償

- **戻り値を検査し忘れても何も起きない。** 例外なら無視すれば上位に伝播するが、
  エラーコードは黙って捨てられる
  → 対策：`[[nodiscard]]` を付ける（未実施。Step 3 で入れる）
- **呼び出し側が冗長になる。** 出力引数のための空オブジェクトを先に宣言する必要がある

```cpp
  Header h{};
  WireError e = unpack_header(buf, len, h);
  if (e != WireError::Ok) { ... }
```

  `Result<T>` なら1行で済む
- **ADR-0005 と不整合。** インタフェース設計と実装で流儀が違う状態

## 検証方法

- **`Result<T,E>` を自作した場合、呼び出し側が実際に短く読みやすくなるか。**
  ならなければ案2で十分だったということ
- **C++23 に移行可能になった時点で `std::expected` に置き換えられるか。**
  置き換えが困難なら、案2への依存がコード全体に染み出していたことになる
- 戻り値の検査漏れが実際に発生するか。発生するなら `[[nodiscard]]` の導入を前倒しする

## 関連

- ADR-0005（`IRouteProvider` が `Result<Route>` を返す）— 現状は不整合
- ARCHITECTURE §3-9（エラーの影響範囲）

- **`Process` 基底クラスに例外の境界処理をまだ置いていない。**
  現状 `main()` は `p.init()` と `p.run()` を素で呼んでおり、
  想定外の例外が飛んだ場合は捕捉されずに `std::terminate` に至る
  → Step 3 で `run()` を try で囲み、`std::throw_with_nested` による文脈付与を実装する
